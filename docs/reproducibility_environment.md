# Reproduction environment

The clean rebuild uses R 4.5.3 for Windows x86-64 and an isolated library populated from the exact installed packages used by this project. This is an **offline, verified copy of installed packages**, not a fresh CRAN installation, source build, or tested `renv::restore()`.

Run from the original repository:

```powershell
& 'C:/Program Files/R/R-4.5.3/bin/Rscript.exe' --vanilla scripts/prepare_isolated_environment.R outputs/clean_rebuild_20261106/project
```

The preparer refuses to overwrite a nonempty target library. It reads each installed DESCRIPTION, resolves Depends, Imports and LinkingTo recursively, copies non-bundled packages, and verifies SHA256 digests of every source and copied package file. `config/environment_packages.csv` records exact versions and aggregate package-tree hashes; `config/environment_runtime.txt` records R, platform and method. Base/recommended dependencies remain in the selected R installation and their versions and tree hashes are also recorded. Neither the source library nor its packages are modified.

Once the manifest exists, preparation refuses source-package version, dependency-set or package-tree hash drift rather than replacing the lock with whatever is currently installed. R 4.5.3 is required. To audit an existing prepared project without copying or writing any files, run:

```powershell
& 'C:/Program Files/R/R-4.5.3/bin/Rscript.exe' --vanilla scripts/prepare_isolated_environment.R outputs/clean_rebuild_20261106/project --verify-only
```

Verification requires matching root and target manifests, the exact isolated package-directory set, every source version/tree hash, and every copied package version/tree hash. It includes the 19 R-standard-library dependencies and 85 isolated packages, rather than checking package versions alone. This validates the locked installed-binary snapshot; it does not test a source installation.

Direct dependencies for the complete executable workflow are digest, dplyr, tidyr, ggplot2, sf, readr, jsonlite, glmmTMB, pdftools and readxl. The last two support source-document inspection. General project preparation mentions renv as an optional inventory check, but executable analysis does not require it. No renv lock is presented as a tested source-restoration route.

Set `R_LIBS_USER` to the clean project's `.local_library` and `R_LIBS_SITE` to an empty string for all child processes. Launch single analysis entry points from the clean project root as:

```powershell
& 'C:/Program Files/R/R-4.5.3/bin/Rscript.exe' --vanilla scripts/run_isolated.R scripts/ENTRY_POINT.R
```

The launcher restricts package search to that isolated library plus the R standard library, verifies exact dependency versions, and rejects loaded namespaces from outside those paths before and after execution. The raw-input rebuild entry point takes its own arguments and has its own isolation checks; invoke it directly with the same environment variables. `--vanilla` prevents user startup files or saved workspaces from entering the run. The orchestrator must copy the new environment scripts and manifest into the clean project after preparation.

The isolated library contains package binaries and native dependencies already installed on this Windows/R platform. It does not establish portability to another operating system or R version. The R-Positron Cache contains nine Windows binary ZIPs and no source tarballs; the package-library cache contains no ZIP/tarball archives. This partial cache is insufficient to restore the full dependency closure. `config/environment_available_archives.csv` records the nine archives and hashes. A network-independent source reinstall is therefore not claimed. Existing raw empirical files, their provenance/hash manifest, project code and the verified package copy are the allowed inputs; derived panels, fit objects and cached figures must be regenerated by the clean-run orchestration.

The environment preparation only establishes the package-copy evidence. The separate clean-run receipt determines whether the complete workflow from original files actually succeeded and whether outputs agreed.

The completed preparation copied 85 non-bundled packages and recorded 19 R-bundled dependencies (104 total). All ten direct pipeline packages loaded under the isolated launcher; loaded namespace paths were restricted to the isolated and R-standard libraries. The smoke receipt records GEOS 3.14.1, GDAL 3.12.1 and PROJ 9.7.1. Its output was moved outside the clean project before raw-input execution so no derived-output directory could satisfy the rebuild.

Executable entry points are inventoried with language, explicit R package mentions and code hashes in config/environment_entry_points.csv. This static inventory supplements the recursive package manifest; it does not infer the workflow order. Portfolio typesetting uses Python reportlab and pypdf, Windows Calibri fonts, and the bundled Node artifact-tool runtime. Those non-R components are outside this R package-copy manifest and require their own runtime/render verification in the portfolio rebuild.
