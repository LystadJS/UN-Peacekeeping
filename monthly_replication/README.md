# MONUSCO monthly replication

This standalone R study covers recorded civilian-targeted violence in Ituri, North Kivu, and South Kivu from January 2015 through December 2025. The manuscript leads with the deployment association, then evaluates next-month incident count forecasts and describes the 2024 South Kivu withdrawal.

## Rebuild

1. Open this directory in R 4.5.3. Install `renv` if needed and run `renv::restore()`. An adjacent historical checkout can supply the pinned Geo-PKO and GED files read-only. To stage public inputs for a standalone checkout, run `Rscript acquire_public.R` after restoring the dependencies.
2. For the primary analysis, place an authorized all-event ACLED export for the Democratic Republic of the Congo in `inputs/acled.csv`. Copy `config/acled_receipt_template.csv` to `inputs/acled_receipt.csv` and enter the actual export date. The requested dates are 2015-01-01 through 2025-12-31. Follow the current ACLED terms for acquisition, attribution, and redistribution. [ACLED access](https://acleddata.com/faq/how-can-i-access-and-use-acled-data)
3. Run `Rscript run.R --render`. Use `QUARTO_BIN` if Quarto is outside the command search path. The command writes its status and evidence to `results/` and creates `manuscript.html`. Set `MONUSCO_MONTHLY_INPUTS` and `MONUSCO_MONTHLY_RESULTS` to override those locations. Use a new results directory when changing source vintages. `--require-primary` returns exit status 2 when the primary association is unavailable. `--panel-only` builds the panel and descriptive handover outputs. If the previous quarterly release is available, run `Rscript compare_quarterly.R` after the build to reconcile original map listings with its correction audit. Override its location with `MONUSCO_QUARTERLY_RELEASE`.
4. Run `Rscript tests/check_pipeline.R` after a build. It checks staged outputs, date gaps, predicted count scores, and insulation from future data using a synthetic fixture.

## Source and review workflow

- The preferred boundary is the OCHA COD-AB ADM2 GeoJSON. The original ZIP contains `cod_admin2.geojson`, staged locally as `inputs/ocha_adm2.geojson`. The file used here has OCHA territory identifiers. The alternative geoBoundaries path requires a complete, unambiguous crosswalk to reference territories before it can run. The available fallback does not distinguish some same-name cities and territories and therefore fails this gate. [OCHA boundary listing](https://data.humdata.org/dataset/cod-ab-cod)
- Read `results/source_manifest.csv`, `results/deployment_lineage.csv`, `results/coverage_review_queue.csv`, and the two event flows before interpreting a model. The deployment ledger currently covers a limited set of South Kivu territory-months in late 2024. Each row documents the evidence and review status. Extend coverage in `config/deployment_coverage.csv` with the exact map key, source link and reasoning. Unreviewed cells remain unknown. Judge forecast and association support from the contributing territories and distinct map changes.
- Supply optional ACLED archives as files inside `inputs/` with the structure in `config/forecast_vintages_template.csv`. Each named archive must independently cover the study start through the last completed eligible history month at export, with the same geography and event scope as the verification extract. The archived series uses a two-month lag for event features because the most recent calendar month may still be incomplete before issuance. The archive is scored against the frozen verification extract. Publication evidence for Geo-PKO as of each issuance is unresolved, so this replay covers history forecasts.
- Keep raw exports, row-level event and map crosswalks, and model outputs local unless their terms permit the intended distribution. `results/run_status.csv` identifies analyses that were run and evidence still needed. The [technical appendix](technical_appendix.md) describes the specifications and interpretation.
